# Comparación de React Doctor con develop

React Doctor 0.9.18, baseline JSON de `git merge-base HEAD origin/develop` (en AUD-17: `6eb5ee36c76759b4628e8b6de0dee34f0f98aedf`): el análisis completo de la base dio 2 errores y 88 advertencias. `react-doctor . --baseline baseline.json --blocking warning --no-score` informó cinco avisos: tres corresponden a la demo movida a nuevos archivos (`no-array-index-as-key`, `rerender-lazy-ref-init` y `async-await-in-loop`) y dos se introdujeron en el header y el chat.

Reproducción de la limitación: el antiguo `pages/notificaciones.tsx` es la demo en la base. La rama conserva esa ruta para la página real y mueve la demo a `pages/notificaciones-demo.tsx`. Al sustituir temporalmente `key={n.id}` por `key={index}` en la página real, un análisis directo muestra `no-array-index-as-key`, pero la comparación nativa no lo informa: empareja por ruta/regla la nueva ocurrencia con la de la demo antigua y presenta como nueva la ocurrencia movida. Una clase temporal `transition-all` sí aparece. Ambos cambios se restauraron.

El gate usa los JSON completos de la base y del árbol actual. Compara multisets de `(plugin, regla, severidad, fingerprint)` por archivo y reconoce copias o renombres detectados por `git diff --find-copies-harder`. Las copias se emparejan antes que la ruta original: así una advertencia nueva en el archivo que reemplazó la demo no absorbe el hallazgo trasladado. Dentro de un mismo archivo, reemplazar un hallazgo por otro idéntico con el mismo fingerprint y el mismo conteo no puede distinguirse con la identidad que expone React Doctor. El gate falla ante JSON incompleto, ausencia de fingerprint o errores de extracción/ejecución; no desactiva reglas.
