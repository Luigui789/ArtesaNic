# Matriz de trazabilidad y cobertura de requisitos V1 (AUD-19)

**Ticket:** AUD-19 (`test(requirements): sustituir expectativas antiguas y trazar cobertura RF RNF RN`).
**Fuentes normativas canónicas:** [requisitos.md](../requisitos/requisitos.md), [reglas-de-negocio.md](../requisitos/reglas-de-negocio.md) y [decisiones V1](../decisiones/v1.md).
**Fuente legible por máquina:** [cobertura-v1.json](cobertura-v1.json).
**Validador automático en CI:** `python infra/scripts/check_requirements_coverage.py`.

## 1. Principios de clasificación y honestidad

- **`AUTOMATED`**: La regla o requisito cuenta con cobertura automatizada real en las capas pertinentes (dominio, API, concurrencia PostgreSQL, smoke HTTP y/o cliente/UI frontend real).
- **`PARTIAL`**: Existe cobertura automatizada real para una parte sustantiva del requisito, pero falta una variante, una validación visual en navegador real o una prueba de carga/despliegue posterior.
- **`MANUAL_EVIDENCE`**: El requisito depende de verificación manual documentada o inspección operacional explícitamente referenciada.
- **`DEFERRED`**: La validación o instrumentación completa corresponde legítimamente a un ticket posterior del plan (`AUD-20` a `AUD-26`).
- **`NOT_IMPLEMENTED`** / **`NOT_VERIFIED`**: Sin implementación o sin verificación actual.
- **Frontera con el modo demo (`DEMO_ONLY`)**: El script `apps/frontend/scripts/check-demo.mjs` y los módulos bajo `apps/frontend/src/mocks/` verifican exclusivamente el entorno de demostración aislado (`VITE_CATALOGO_API=mock`) y **nunca** se contabilizan como evidencia de requisitos de V1.
